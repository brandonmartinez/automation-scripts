# GitHub Copilot Configuration

## Project Context

Project automation scripts default to **zsh**. Preserve existing shebangs: `media/photo-multicrop2.sh` and the Squad `sync-mesh.sh` template are **Bash** exceptions. New project automation scripts should:

- Use `#!/usr/bin/env zsh` shebang
- Follow zsh syntax and conventions
- Be compatible with zsh-specific features

The owner-authorized exception is the Hazel-connected PDF/paperwork, guitar-tab,
and video AI import migration: `automation_lib/` uses Python 3.11+ and the
standard library, behind the existing executable zsh paths. Keep parsing,
decisions, structured state, and queue orchestration there. Preserve specialist
tool argv, AI providers/models/prompts, and the paperwork backfill JSON contract.
Do not extend this exception to unrelated automation without approval.

## Code Generation Guidelines

When suggesting code for this project:

- Assume zsh for project automation scripts, but preserve Bash syntax in the existing Bash exceptions
- Use zsh array syntax: `"${array[@]}"` for expansion, `"${!array[@]}"` for indices
- Prefer zsh built-ins and idioms
- Use zsh-compatible parameter expansion
- Follow the existing logging patterns from `utilities/logging.sh`
- When invoking common nix utilities (e.g., cat, ls, grep, sed), prefix them with `command` to bypass user-defined aliases in the shell profile
- Favor pure zsh scripts—do not introduce Python, Node, Ruby, or other languages unless the user explicitly approves and there is a compelling benefit; ask before suggesting any non-shell helper code
- For the authorized Hazel Python workflows, use `unittest` (`npm run test:hazel`) with disposable HOME/cache/state/output roots and a closed fake-tool PATH. Never run live inference, OCR/media jobs, credential lookup, or production queues during validation.
- Keep zsh formatting manual and validate with `zsh -f -n`; shfmt and ShellCheck do not support zsh. Follow the dialect-scoped editor configuration and commands documented in `README.md`.

## Script Standards

- Set shell options: `set -o errexit -o nounset -o pipefail`
- Use proper error handling with exit codes
- Include comprehensive logging with emoji indicators
- Follow the established directory structure and naming conventions
